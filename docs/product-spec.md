# Product Spec

来源：根目录 `WeekendTravel_ProductDoc.md` 和补充的 2 页设计文档。本文件只沉淀长期开发所需的产品事实，不替代原始产品文档。

## 一句话目标

WeekendTravel 是一款“本地短时活动规划与执行 Agent”：用户发一句自然语言，系统自动完成意图抽取、活动规划、可行性校验、异常重排，最后输出可一键确认的方案，并模拟预约、下单、配送、转发消息等执行动作。

核心体验不是“推荐列表”，而是“可执行方案 + 可确认执行包 + 实时状态日志”。

## 目标用户

- 想在半天或几个小时内安排本地活动的人。
- 临时有空、懒得查多个 App、希望系统直接给出可执行安排的用户。
- Demo 中重点覆盖两类用户：
  - 家庭用户：有孩子、距离和体力约束更明显，需要亲子友好与餐饮适配。
  - 朋友出行用户：多人活动，需要兼顾玩、吃、拍照和路线效率。

## 核心场景

### 家庭场景

Demo 输入：

```text
今天下午是空的，想和老婆孩子出去玩几个小时，别离家太远。孩子5岁，老婆最近在减肥，帮我安排一下。
```

系统需要识别亲子、近距离、孩子年龄、低负担餐饮、下午短时活动等约束，并输出活动、餐饮、路线和执行动作。

### 朋友场景

Demo 输入：

```text
今天下午4个人出去玩，2个男生2个女生，不想离家太远，帮我安排一个能玩、能吃、能拍照的下午。
```

系统需要识别多人、社交、拍照、玩吃结合、近距离等约束，并输出适合朋友局的活动组合。

## 非目标

- 不接入真实支付、真实预约、真实配送、真实第三方地图或真实商家库存。
- 不做通用旅行平台，不覆盖跨城市长途旅行。
- 不让 LLM 决定规划策略；规划、校验、重排由状态机和规则控制。
- 不在初始化阶段实现完整业务链路。
- 不在未核验官方文档前锁定 OpenAI SDK 版本或模型名。

## 核心价值

- 一句自然语言输入，而不是多字段表单。
- 输出可执行方案，而不是信息列表。
- 异常时自动 Plan B，而不是让用户自己换。
- 一键确认后模拟完成下单、预约、备注和消息生成。
- 通过 SSE 展示 Agent 状态、Tool 调用和异常重排，让 Demo 可解释、可观察。

## 成功标准

- 主链路：`POST /api/plan` -> `GET /api/plan/{planId}/stream` -> `plan_ready` -> `POST /api/plan/{planId}/execute` -> `done`。
- Golden Case 共 21 条：家庭 7 条、朋友 7 条、边界 7 条。
- SLO：
  - 端到端规划耗时 P95 小于等于 30 秒。
  - 方案可行率大于等于 90%。
  - 意图抽取准确率大于等于 85%。
  - 异常注入场景下 Plan B 触发准确率 100%。
  - 正常非注入场景下 Plan B 触发率小于等于 30%，否则说明 Plan A 召回质量不足。

## Planning 策略摘要

- 采用“确定性状态机 + 大模型辅助理解”：状态机控制流程，LLM 只做自然语言理解和最终话术生成。
- 候选排序使用可解释公式作为初始口径：`score = 0.4 * 相关性 + 0.3 * 距离 + 0.2 * 评分 + 0.1 * 余位健康度`。
- 约束分级：
  - P0 硬约束：安全、年龄适配、时间可行、人数可容纳。
  - P1 软约束：距离近、可订位、饮食偏好、排队可接受。
  - P2 加分项：评分高、网红属性、拍照氛围、座位偏好。
- 重排终止条件：单个 plan 最多 3 次 replan，累计 Tool 调用不超过 30 次，规划超过 25 秒进入 `DEGRADE`。

## Demo 必须可见的能力

- 输入一句话后进入规划状态。
- 右侧日志实时展示状态机和 Tool 调用。
- `CLARIFY` 只提出一个最关键反问。
- 异常注入后触发 Plan B，并在日志和方案卡上明确高亮。
- 用户可在确认前微调方案，最多 3 次。
- 确认执行后能看到执行动作逐条完成，最终进入 `DONE` 或明确降级状态。
