# 本地短时活动规划 Agent UI 重设计方案

## 1. 重设计核心思路：从“开发者后台”到“出行主理人”

原方案的双栏布局（左栏对话，右栏状态机日志）存在严重的**“开发者视角”问题**：
1. **缺乏出行场景的空间感**：纯文本日志无法传达“本地生活”的距离、路线与地理概念。
2. **认知负荷过高**：用户不关心状态机叫 `RECALL` 还是 `VALIDATE`，只关心“你在帮我找什么”以及“找到了没”。
3. **缺乏情感化与确定感**：周末出游是令人期待的事，冷冰冰的日志会放大 Agent 的“机械感”，方案替换时缺乏平滑过渡。

### 新设计理念：Map-Centric + Progressive Disclosure（地图为中心 + 渐进式展现）
- **对标产品**：Apple Maps / 高德地图的顺路规划（空间感） + ChatGPT Canvas / Perplexity（Agent过程可视化） + 小红书（生活感与卡片流）。
- **核心转变**：将后台的“六步状态机”翻译为前端用户能感知的**“行动阶段”**；将“右侧日志”转化为**“地图上的动态轨迹与浮层提示”**。

## 2. 整体布局与视觉风格

### 2.1 视觉风格
- **基调**：轻量、呼吸感、微拟物。
- **色彩**：
  - 主色调：活力橙/暖阳黄（代表周末、休闲、活力），取代传统的科技蓝。
  - 辅助色：地图浅灰底色，卡片纯白，成功状态绿，警告/排队状态琥珀色。
- **排版**：圆角大卡片，柔和阴影，重点信息（时间、距离、余位）加粗高亮。

### 2.2 布局结构：沉浸式地图 + 底部抽屉

摒弃左右分栏，采用**全屏地图打底 + 底部可拉伸抽屉**的移动端优先设计（Desktop端抽屉可吸在右侧）。

## 3. Agent 流程 UI 映射（状态机翻译）

将不可见的状态机，转化为地图上的视觉反馈和卡片的渐进式加载。

| 后台状态机 | 用户感知 | UI 表现 |
| :--- | :--- | :--- |
| **INTENT** | 理解我的想法 | 输入框解析出标签：`👨‍👩‍👧 家庭` `🕐 4小时` `📍 30min内`，地图自动以家为圆心画出30分钟半透明圆圈。 |
| **SKELETON** | 规划时间线 | 底部抽出空白时间轴：`14:00 [活动待定]` → `17:30 [晚餐待定]` → `19:30 [散步待定]`，地图显示预规划路线虚线。 |
| **RECALL** | 正在找地方 | 地图圈内冒出探照灯动画，POI 图标像水泡一样在地图上弹出来（半透明态）。 |
| **VALIDATE** | 确认靠不靠谱 | 地图上POI变实，路线虚线变实线。抽屉弹出微提示：“发现青禾花园排队70分钟，正在替换...” |
| **PACK** | 方案出炉 | 时间轴卡片翻转，展示最终方案图片与信息，地图聚焦到最终路线上。 |
| **EXECUTE** | 帮我订位 | 卡片状态变为“锁定中...”，成功后变为绿色“已预订”。 |

## 4. 核心组件详细设计

### 4.1 对话与输入区
- **悬浮输入框**：置于底部抽屉的最上方，类似 ChatGPT / Perplexity。
- **结构化反问**：当置信度 < 0.7 时，不使用纯文本反问，而是弹出**选择器胶囊**。
  - *示例*：“孩子多大呀？ 👶 0-3岁 / 👧 3-6岁 / 🧑 6岁以上”

### 4.2 Agent 透明度面板
取代原来的右栏日志，使用类似 GitHub Copilot 的迷你气泡。
- **正常情况**：折叠为一行状态：`🤖 已找到3个备选，正在校验排队与距离...`
- **异常情况**：自动展开为一条**智能替换卡片**。
  - *UI 示例*：`⚠️ 青禾花园排队过长(70min) → 🔄 已自动替换为：清禾家庭餐厅(可订位) [查看原因]`

### 4.3 时间轴行程卡
采用**横向滑动卡片**，而非纵向长列表。每张卡片包含：
- **左侧**：时间节点（大号字体，如 17:30）
- **中部**：POI 图片（圆角，高视觉吸引力）+ 名称 + 核心标签（`低卡` `有儿童椅`）
- **右侧**：状态标识（`余3桌` `已锁定`）+ 步行/车程分钟数（连接到下一张卡片的箭头：`🚗 15min`）

### 4.4 Plan B 切换器
当存在多个可行方案时，不是展示干涩的 A/B 日志，而是在地图和卡片上提供**无感切换**。
- 时间轴上方出现分段控制器：`[Plan A: 亲子优先] / [Plan B: 吃货优先]`
- 点击切换时，地图路线和底部卡片有平滑的过渡动画。

### 4.5 一键执行与分享
- **执行按钮**：大面积毛玻璃质感按钮。点击后，卡片上的“预订”状态像进度条一样逐个点亮（买票 → 订座 → 备注）。
- **分享功能**：点击分享，生成类似 Apple Watch 健身圆环的精美分享图（包含行程缩略图、时间和一句话总结），或直接生成微信卡片格式，而非干瘪的文本。

## 5. 关键交互流：异常重排的 UI 演示

**场景**：首选餐厅满座排队70分钟，触发 Replan。

1. **触发**：Agent 校验时，地图上“青禾花园”图标变红闪烁，底部抽屉自动上推。
2. **反馈**：出现一张替换卡片：
   ```
   ⚠️ 遇到小问题
   青禾花园当前排队 70 分钟，会让你们游玩时间缩短。
   🤖 建议替换为：【清禾家庭餐厅】
   - 同样有儿童椅，低卡菜单
   - 距离乐园更近（步行3分钟）
   - 17:30 有4人空桌
   [ 保持原样排队 ]   [ ✅ 采用智能替换 ]
   ```
3. **执行**：若用户点击替换，或 Agent 自动替换，地图路线微调，时间轴卡片无缝翻转更新。

## 6. 演示 Demo 输出效果

针对原来的演示输入，用户看到的不再是满屏 JSON 和文本，而是：

**输入后 5 秒**：
- 地图以家为中心画圈，底部出现骨架屏时间轴。

**输入后 15 秒**：
- 地图弹出 3 个 POI，底部弹出提示：“正在检查奇妙亲子乐园余票...”

**输入后 25 秒（方案生成）**：
- 底部抽屉完全展开，横向展示 3 张精美卡片：
  - 卡片1：14:00 奇妙亲子乐园（已出票 2大1小）
  - 卡片2：17:30 清禾家庭餐厅（已锁定4人桌）
  - 卡片3：19:00 万象城甜品站（可随性前往）
- 地图显示完整的彩色驾车/步行路线。
- 显眼的大按钮：`✅ 确认全部并生成行程单`
- 侧边按钮：`📤 一键发给老婆`

## 7. 技术实现建议 (UI侧)

- **地图引擎**：Mapbox GL JS / 高德地图 JS API 2.0（支持 3D 视角、平滑路线绘制、自定义 DOM 图标覆盖物）
- **动画库**：Framer Motion（用于卡片翻转、状态机切换、抽屉拉伸的物理弹性动画）
- **UI 组件**：Tailwind CSS + Radix UI（便于实现毛玻璃效果、响应式布局及无障碍支持）
